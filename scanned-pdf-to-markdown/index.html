Scanned PDF to text or Markdown: OCR options compared (free and API)

First find out which kind of PDF you have. Try selecting text in a viewer: if you can, it is born-digital and you don't need OCR. If not, it is a scan (an image per page) and you need OCR.

Born-digital PDFs

  • pdftotext -layout file.pdf out.txt (poppler) for plain text.
  • Python: pymupdf4llm.to_markdown("file.pdf") keeps headings, lists and tables as Markdown, handy for LLM/RAG pipelines.

Scanned PDFs, free and local

ocrmypdf --deskew --clean -l eng+deu scan.pdf searchable.pdf
pdftotext -layout searchable.pdf scan.txt

ocrmypdf uses Tesseract and adds a text layer. Install the right language packs (tesseract-ocr-deu etc.). Quality depends heavily on the scan: 300 dpi, straight pages and good contrast matter more than the engine. Old typefaces like Fraktur need their own model.

Vision-LLM OCR

Newer models (e.g. Mistral OCR, open models such as PaddleOCR or DeepSeek-OCR) handle complex layouts and tables better, but need a GPU or a paid API, and can occasionally "fix" text that wasn't there. Check numbers carefully.

Many PDFs from URLs, no setup

The PDF to Text & Markdown (OCR) Actor on Apify takes PDF URLs, detects per page whether OCR is needed, cleans up scans before Tesseract (19 languages including Fraktur), and returns text and Markdown per page. Text pages are billed for at most 15 pages per PDF, OCR per page; failed files are free.

Checklist

  • Spot-check numbers, dates and names against the image.
  • Keep the page number with each chunk if you feed it into search or an LLM.
